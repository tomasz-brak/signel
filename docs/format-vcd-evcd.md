# IEEE Std 1364-2001 VCD & EVCD Specification Guide

This guide details the **IEEE Std 1364-2001** (Verilog Hardware Description Language) Value Change Dump (**VCD**) and Extended Value Change Dump (**EVCD**) file formats supported by `signel`.

---

## 1. Overview of IEEE 1364-2001 Clause 18

Clause 18 of IEEE Std 1364-2001 specifies two ASCII file formats for recording state changes in digital simulations:
1. **Standard VCD (Clause 18.2)**: Introduced in IEEE Std 1364-1995. Tracks 4-state logic (`0`, `1`, `x`, `z`) across registers and nets.
2. **Extended VCD (EVCD, Clause 18.3)**: Added in IEEE Std 1364-2001. Tracks boundary port states with **signal drive strength** and **port directionality** (inputs from test fixture, outputs from Device Under Test, and bidirectional states).

---

## 2. File Structure

Both VCD and EVCD files consist of two main sections:
1. **Header Section**: Contains simulation metadata (`$date`, `$version`, `$timescale`), scope hierarchy (`$scope`, `$upscope`), variable/port declarations (`$var`), and closes with `$enddefinitions $end`.
2. **Value Change Section**: Timestamp records (`#<time>`) followed by value change events.

### Header Keywords

| Keyword | Description | Example |
|---|---|---|
| `$date` | Date simulation was executed | `$date Oct 14 12:00:00 2026 $end` |
| `$version` | Simulator name and version | `$version IEEE 1364-2001 Simulator $end` |
| `$timescale` | Time unit per simulation tick | `$timescale 1ns $end` |
| `$scope <type> <name>` | Hierarchical scope definition | `$scope module top $end` |
| `$upscope` | Return to parent scope | `$upscope $end` |
| `$var <type> <size> <id> <name>` | Variable or port definition | `$var wire 1 ! clk $end` |
| `$enddefinitions` | Marks end of header | `$enddefinitions $end` |

---

## 3. Standard VCD Value Changes (18.2)

In standard VCD, value change lines follow these formats:
- **Scalar changes** (1-bit): `<value><identifier>`
  - Values: `0`, `1`, `x`, `X`, `z`, `Z`
  - Example: `1!` (sets signal with ID `!` to `1`)
- **Vector changes** (multi-bit): `b<binary_digits> <identifier>`
  - Example: `b10101011 @` (sets signal `@` to binary `10101011`)
- **Real numbers**: `r<real_number> <identifier>`
  - Example: `r3.14159 #`
- **Time markers**: `#<integer>`
  - Example: `#100` (advances simulation time to 100)

---

## 4. Extended VCD (EVCD) Value Changes (18.3)

Extended VCD files are generated by the Verilog system task:
```verilog
$dumpports(module_instance, "ports.evcd");
```

In EVCD:
- Variables are declared with type `port`:
  ```text
  $var port 1 ! clk $end
  $var port 8 @ data [7:0] $end
  ```
- Value changes begin with the token `p`:
  ```text
  p<state_characters> <dir_in> <dir_out> <identifier>
  ```
  or simply `p<state_characters> <identifier>`.

### The 23 IEEE Std 1364-2001 EVCD State Characters

IEEE Std 1364-2001 Clause 18.3 Table 18-1 specifies 23 characters encoding signal strength and direction:

| Character | Driver Source | Input Value | Output Value | Composite Value | Strength / Description |
|:---:|:---:|:---:|:---:|:---:|:---|
| **`D`** | Test Fixture | `0` | `Z` | `0` | Test fixture driving strong Low |
| **`U`** | Test Fixture | `1` | `Z` | `1` | Test fixture driving strong High |
| **`N`** | Test Fixture | `X` | `Z` | `X` | Test fixture driving unknown |
| **`Z`** | Test Fixture | `Z` | `Z` | `Z` | Test fixture in High-Impedance |
| **`d`** | Test Fixture | `0` | `Z` | `0` | Test fixture driving weak Low |
| **`u`** | Test Fixture | `1` | `Z` | `1` | Test fixture driving weak High |
| **`L`** | DUT | `Z` | `0` | `0` | Device under test driving strong Low |
| **`H`** | DUT | `Z` | `1` | `1` | Device under test driving strong High |
| **`X`** | DUT | `Z` | `X` | `X` | Device under test driving unknown |
| **`T`** | DUT | `Z` | `Z` | `Z` | Device under test in High-Impedance |
| **`l`** | DUT | `Z` | `0` | `0` | Device under test driving weak Low |
| **`h`** | DUT | `Z` | `1` | `1` | Device under test driving weak High |
| **`0`** | Both / Port | `0` | `0` | `0` | Port state Low |
| **`1`** | Both / Port | `1` | `1` | `1` | Port state High |
| **`?`** | Both / Port | `X` | `X` | `X` | Port state Unknown |
| **`F`** | Conflict | `X` | `1` | `X` | Test fixture X, DUT 1 |
| **`A`** | Conflict | `0` | `X` | `X` | Test fixture 0, DUT X |
| **`a`** | Resolved | `0` | `0` | `0` | Test fixture 0, DUT 0 |
| **`B`** | Conflict | `1` | `X` | `X` | Test fixture 1, DUT X |
| **`b`** | Resolved | `1` | `0` | `X` | Test fixture 1, DUT 0 (conflict) |
| **`C`** | Conflict | `X` | `0` | `X` | Test fixture X, DUT 0 |
| **`c`** | Resolved | `X` | `1` | `X` | Test fixture X, DUT 1 |
| **`f`** | Both | `Z` | `Z` | `Z` | High-impedance both sides |

## 5. EVCD Handling in `signel`

`signel` natively detects EVCD files and provides flexible decoding via `evcd-mode`:
- **`"composite"`** (default): Resolves each character to its resultant logic state (`0`, `1`, `x`, `z`) as observed on the wire.
- **`"input"`**: Isolates the input component driven by the test fixture.
- **`"output"`**: Isolates the output component driven by the DUT.
- **`"raw"`**: Displays the exact IEEE 1364-2001 state character (`D`, `H`, etc.).
